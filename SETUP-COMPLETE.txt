🎯 KEY TECHNICAL DETAILS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

API Architecture:
  • Single API server handles all 3 clients
  • Menu stored in data/store.json (JSON persistence)
  • Banners, settings, content in separate JSON files
  • No database - file-based (easy to understand)

Data Flow:
  Admin Panel (edit) → POST /api/admin/menu → data/store.json
                              ↓
  Both App & Website ← GET /api/mobile/menu ← data/store.json

Pricing:
  • Original price stored: price (e.g., 500)
  • Offer stored: offerPercentage (e.g., 20)
  • Calculated: salePrice = price * (1 - offerPercentage/100)
  • Cart uses salePrice, not price (FIXED in Phase 2)

No Rebuild Needed:
  • App fetches meals on every load/refresh
  • Web fetches on page load
  • React/React Native contexts handle API updates
  • MenuContext re-renders when data changes
